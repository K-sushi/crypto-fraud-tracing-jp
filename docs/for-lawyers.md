# 弁護士・法律事務所の方へ

被害者から暗号資産詐欺の相談を受けた時の、**初動の資料づくり**に使う想定です。
法的な判断 (請求の構成・保全の要否・管轄) は先生方の領域で、ここでは扱いません。

## 受任直後に揃えるもの (依頼者から)

1. 送金に使ったウォレットのアドレスと、送金した取引 ID (ハッシュ)
2. 送金の日時と金額、送金先として指示されたアドレス
3. 相手とのやり取り (SNS・メッセージ・サイトの画面)。**元の端末から消さない**よう依頼者に伝える

## このリポジトリが出す資料

- **資金の流れ図と一覧**: 送金先から、中継・ブリッジを経て、どの取引所の入金先らしきアドレスに入ったか
- **証拠保全ログ**: 取得した全ての API 応答の SHA256・UTC 時刻・取得手順 (`skill/phases/report.md`)
- **事実 / 推定 / 未確認の区別**: 報告書の各主張に確度の区分が付く

## 資料の使いどころ (例。可否と手続きは各事務所の判断)

- 取引所の入金先と推定できたアドレスについて、**その取引所への照会や保全の申入れ**を検討する際の裏付け
- 警察への被害届・相談に添付する、**整理済みの時系列資料**
- 依頼者への説明 (「どこまで追えて、どこから先は追えないか」)

## してはいけないこと

- 報告書の「推定」を「事実」として外部に出すこと。推定は推定と書く。
- アドレスの持ち主を、この資料だけで特定・公表すること。名誉毀損のおそれがあります。
- AI が書いた文章を、原データと照合せずに提出すること。

## 追跡が難しい典型

- ミキサー (資金を混ぜて出所を分かりにくくするサービス) を経由した場合
- 取引所を介さず、個人間で現金化された場合
- 取引所が海外で、照会に応じない場合

こうした場合は「追えなかった」と報告書に残すのが正しい結果です。
